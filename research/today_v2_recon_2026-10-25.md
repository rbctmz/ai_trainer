## Б. Расхождения TSB/CTL/ATL и готовности

Математика одна: `BanisterModel` 42/7 (`models/banister.py:44-47`); `BANISTER_K1/K2/TAU1/TAU2`, `CTL_WINDOW`, `ATL_WINDOW` в `config/settings.py:140-147` — **мёртвые константы, не потребляются** (Observed).

Показание собирают четыре пути (Observed, файл:строка):

1. **Снапшот готовности** — `models/readiness.py:753` (`_tsb_metrics`): `get_activities(90)` → Banister с достройкой нулей до athlete-сегодня; результат persisted в `tsb_json` при каждом синке.
2. **План** — `/api/planning/status` → `api/planning_service.py:558` (`current_status`) → `_current_signals` (`:479`) → `assemble_signals` на `get_activities(90)`. Окно режется включительной границей `today−N`, что документировано как расхождение с каноническими границами (`api/routers/dashboard.py:67-71`, находка ревью #614).
3. **Обзор** — `api/routers/dashboard.py:50-89`: кадр 30 дней для отображения + отдельный канонический ряд через `load_metrics_window_bounds` (`models/readiness.py:31`) + отдельный ряд ≥84 дней для ACWR.
4. **Коуч** — `models/ai_tools.py:952`: окно 90 (`COACH_LOAD_METRICS_WINDOW_DAYS` = `LOAD_METRICS_WINDOW_DAYS`) + контекст фиксируется в момент LLM-вызова.

Системные причины расхождений:

- **Внутридневной дрейф** (Observed, БД): снапшоты 2026-10-24 — 12:47 UTC: CTL 20.9 / ATL 24.9 / TSB −4.0; 13:50 UTC (после синков): CTL 19.0 / ATL 13.9 / TSB 5.0. Вход пересчитывается после синков.
- **Две шкалы TSS в одной таблице** (Observed, БД): `activities.tss` за 90 дней Σ=2375 против `source_tss` Σ=4757 — ровно 2×, причём `source_tss` ≡ `garmin_training_load` (n=74 в обоих случаях). Поверхности, читающие разные колонки/источники, дают разные CTL/ATL.
- **Независимый пересчёт** (Verified by: read-only python по `ai_trainer.db`): 42/7 по колонке `tss` с нулями до сегодня — CTL 23.9 / ATL 19.4 / TSB 4.4; без сегодня — CTL 23.4 / ATL 16.1 / TSB 7.4; 28-дневный CTL без сегодня — 20.9 (совпал с утренним снапшотом).
- Готовность 77.6 против 78 — чисто отображение: снапшот хранит 77.6, web округляет (`Math.round`). (Inferred: точная атрибуция 20.8/19.9/1.4/0.5 к поверхностям не завершена — нужны значения с экранов.)

**Предложение источника истины:** persisted `readiness_snapshots` (score, status, `tsb_json`, `observed_at_utc`) — уже пишется каноническим способом; `/api/today` его отдаёт. Плану/Обзору/Коучу читать те же поля либо одну общую функцию с каноническими границами `load_metrics_window_bounds`, одним якорем `athlete_local_date` и одной зафиксированной колонкой TSS. Разбор двух шкал TSS — отдельная задача.

## В. Вывод коуча одним предложением

- Готового LLM-брифинга **нет** (Observed): «briefing» в `/api/today` — только настройка частоты (`api/briefing_settings.py`, ключ `briefing_frequency` в `user_settings`; `PUT /api/settings/briefing`).
- Текст «что делать сегодня» уже существует и детерминирован: **`decision_story`** (`models/today_decision_story.py`, компоновка чистая, evidence-bound; вызов из `api/today_snapshot.py:151`). Поля `next_action.summary` / `recommendation.summary` — готовые однострочники; строки `evidence` (readiness, subjective_wellness, session) — готовое обоснование. Хранится в payload `/api/today`, считается правилами на каждый запрос (миллисекунды), LLM не участвует — стоимость нулевая.
- LLM есть только в чате `/api/coach` (`models/ai_providers.py`; провайдер из env, дефолт `gpt-3.5-turbo` (`config/settings.py:59`); `AI_RESPONSE_MAX_TOKENS=1800` (`config/settings.py:80`), короткий чат — 300 токенов (`models/ai_coach.py:44`); явного таймаута и учёта стоимости/латентности не найдено).
- **Рекомендация:** быстрый путь — первое предложение `decision_story` (правила, 0 ₽). LLM-фразу можно добавить позже отдельным кэшируемым путём (1 вызов/день), но правилам она сейчас не нужна.

## Д. Архитектура статусов групп

- Считать **на сервере, в `/api/today`**: пороги — доменная семантика; ui_standard (`docs/design/ui_standard.md:20`) запрещает UI создавать шкалы/пороги, которых нет в контракте. Factors готовности уже несут `baseline`/`deviation`/`evidence` — compose идёт над существующими данными, без новых расчётов.
- Минимальный аддитивный контракт:

  ```
  signals: { summary, groups: [{ key, status: normal|watch|attention,
    items: [{key, label, value, unit, baseline, deviation, status, note}], advice? }] }
  readiness_history: [{date, score}]        // 14 дней, из readiness_snapshots
  sync_freshness: [{source, last_sync_at}]  // из sync_cursors
  week: { planned_tss, actual_tss, days: [{date, status}] }
  ```

- Конфиг порогов — один файл: вариант A — `config/thresholds.json` в репо + загрузчик с дефолтами из текущих констант; вариант B — `user_settings` в БД (прецедент: `briefing_frequency`), правка без коммита.
- Сосуществование с текущими блоками `/today`: группы «Восстановление»/«Самочувствие» дублируют карточку «Состояние» — «Сигналы» должна стать единственной витриной метрик (ui_standard: один показатель не повторяется независимой сводкой), в «Состоянии» остаётся кольцо/статус/полоска 14 дней. «Что требует внимания» (gate-конфликты) — доменные события, не метрики: не заменять. ProposalCard, обратная связь, подсказка Garmin — без изменений. `AdherenceStrip` естественно превращается в блок «Эта неделя». Коуч-карточка = разбор `TodayDecisionStoryFull`: однострочники → «Коуч», workout → «Сегодня», evidence → раскрытие.
