# Экран «Сегодня» v2: разведка и принятые решения

- **Дата разведки:** 2026-10-25; решения владельца зафиксированы тем же числом.
- **Статус:** итоговая версия (read-only разведка + принятые решения). Код в момент разведки не менялся; БД читалась только в `mode=ro`.
- **Коммит 2 issue [#725](https://github.com/rbctmz/ai_trainer/issues/725) отменён владельцем**, v2 его заменяет (issue B); шаг 1 (#725, токены) перенесён в v2 как коммит B0. Метки достоверности: `Observed` — код/БД с файл:строка; `Verified by` — независимые read-only пересчёты; `Inferred` — вывод, требующий проверки.

## Решения владельца (2026-10-25)

1. **Каноническая шкала TSS = `activities.tss`.** `source_tss`/`garmin_training_load` — провенанс и кросс-чек (Garmin Training Load не считается TSS). Фикс шкалы — только после сверки с Intervals.icu в задаче A2.
2. **Единый источник чисел** — persisted `readiness_snapshots` (`score`, `status`, `tsb_json`, `observed_at_utc`); один путь расчёта для всех поверхностей (задача A). Атрибуция владельца по скриншотам: «Обзор» и боковая панель «Коуча» показывали CTL 19.9 / TSB 0.5 (снапшот), «План» — CTL 20.8 / ATL 19.4 / TSB 1.4 (путь `planning_service`); готовность 77.6/78 — округление, не баг.
3. **«Коуч» — правила, без LLM:** однострочник из `decision_story` (`recommendation.summary`/`next_action.summary`), две строки обоснования, ссылка «Открыть брифинг →». Переключатель «Брифинг каждое утро» остаётся daily/conflicts_only, подпись показывает текущий режим; в режиме «только конфликты» карточка «Коуч» показывает «Конфликтов нет», если конфликтов нет.
4. **Пороги — JSON в репо** (`config/thresholds.json`), дефолты из текущих констант; пороги TSB/ACWR помечены provisional до повторного бэктеста на скорректированной шкале (после A2).
5. **Самочувствие:** субъективное «Качество сна» не влияет на статус группы (объективный сон — в «Восстановлении»); норма «Среднее» и лучше, чип только на «Плохое»; статус группы определяют остальные поля; травма кроме «Нет» = «Внимание». Нормы — в JSON.
6. **«Внимание» по сну:** < 5 ч или score < 30.
7. **Свежесть синхронизации:** `sync_cursors.updated_at` по самому старому источнику; пороги группы «Данные»: Следить > 24 ч, Внимание > 48 ч.
8. **Полоска готовности за 14 дней:** из `readiness_snapshots`; дни без записи — пустой столбик.
9. **«Эта неделя»:** будущие дни до конца недели; «пропущено» = прошедший день с планом без факта; выполнение считается относительно плана **на текущий день**, не всей недели.
10. **Узкий экран, порядок:** готовность и «Сегодня» → «Коуч» → «Сигналы» → «Эта неделя» → «Вчера».
11. Тултип готовности в web (40/70) приводится к логике бэкенда 40/60/75 попутно (задача A).
12. В каждом коммите v2 затронутые e2e обновляются вместе с компонентом — каждый коммит зелёный.

## Б. Числа: расхождения и канон

Математика одна — `BanisterModel` 42/7 (`models/banister.py:44-47`); `BANISTER_*`/`CTL_WINDOW`/`ATL_WINDOW` в `config/settings.py:140-147` — мёртвые константы (Observed). Четыре пути сборки входа (Observed):

1. Снапшот готовности — `models/readiness.py:753` (`_tsb_metrics`), persisted в `tsb_json`;
2. План — `api/planning_service.py:479` (`_current_signals`) на `get_activities(90)` с включительной границей `today−N` (находка ревью #614, комментарий `api/routers/dashboard.py:67-71`);
3. Обзор — `api/routers/dashboard.py:50-89`: кадр 30 дней + канонический ряд `load_metrics_window_bounds` + отдельный ряд ≥84 дней для ACWR;
4. Коуч — `models/ai_tools.py:952`: окно 90 + контекст фиксируется в момент LLM-вызова.

Системные причины (Observed/`Verified by`): внутридневной дрейф снапшотов после синков (2026-10-24: 12:47 UTC CTL 20.9/ATL 24.9/TSB −4.0 → 13:50 UTC 19.0/13.9/5.0); две шкалы в `activities` (`tss` Σ90д=2375 против `source_tss` Σ=4757 — ровно 2×, `source_tss` ≡ `garmin_training_load`); независимый пересчёт 42/7 по `tss` с нулями до сегодня — CTL 23.9/ATL 19.4/TSB 4.4, 28-дневный CTL без сегодня — 20.9.

**Решение:** канон `activities.tss`, одна функция расчёта (канонические границы `load_metrics_window_bounds`, фильтр мультиспорт-конвертов, zero-fill до athlete-якоря, окно 90), потребители — снапшот, `planning_service`, dashboard, `ai_tools`; «сегодняшние» числа UI — из `readiness_snapshots.tsb_json`; одно округление (сервер 0.1; кольцо — int). Шкалу не фиксировать до сверки с Intervals.icu (A2).

## В. Вывод коуча

Готового LLM-брифинга нет: «briefing» в `/api/today` — только настройка частоты (`api/briefing_settings.py`). Текст «что делать сегодня» — детерминированный `decision_story` (`models/today_decision_story.py`; вызов `api/today_snapshot.py:151`): `next_action.summary`/`recommendation.summary` — однострочники, `evidence` — обоснование. LLM только в чате `/api/coach` (`models/ai_providers.py`, дефолт `gpt-3.5-turbo`, `AI_RESPONSE_MAX_TOKENS=1800`, чат 300 токенов; таймаут/стоимость не инструментированы). **Решение:** правила, без LLM.

## Г. Пороги: бэктест и принятые значения

Объём истории: HRV/пульс/сон/активности с 2026-04-29 (~180 дней; за 90 — n=88–90), готовность с 2026-07-14, самочувствие с 2026-08-06 (80 записей), TSB-история — 53 дня из последних 90.

Распределения за 90 дней (`Verified by`): HRV p10 26 / p25 30.8 / p50 35 мс; пульс покоя p10 55.9 / p50 59 / p90 62; сон p10 5.5 / p25 6.6 / p50 7.3 ч (score p10 44 / p25 53.8 / p50 67.5); TSB p5 −6.7 / p50 3.6 / max 16.5.

**Принятые пороги** (бэктест на 90 днях; доля срабатываний — в скобках):

| Сигнал | Следить | Внимание |
|---|---|---|
| HRV (отклонение от базы 28 д) | < −12% (20%) | < −24% (5%) |
| Пульс покоя (elevation) | ≥ +3 bpm (14%) | ≥ +4.1 bpm (6%) |
| Сон | < 6 ч или score < 40 (16%) | < 5 ч или score < 30 (6%) |
| TSB **provisional** | < −5 (8%) | < −10 (2%) |
| ACWR **provisional** | > 1.3 (12%) | > 1.5 (2%) |
| Свежесть данных (старейший источник) | > 24 ч | > 48 ч |
| Самочувствие | отклонения — чипы; статус группы по правилам ниже | травма кроме «Нет» — «Внимание» |

TSB/ACWR — provisional: пересчитать бэктест после A2 (скорректированная шкала). Генерические пороги −20/−30 у владельца не достигались ни раза (min −11.7 за 90 дней).

Нормы самочувствия (в JSON): sleepQuality — норма «Среднее» и лучше, чип только на «Плохое», **в статусе группы не участвует**; soreness/fatigue/stress — норма «Низкий/Низкая»; mood — «Хорошее» и лучше; motivation — «Средняя» и лучше (чип только «Низкая»); hydration — «Нормальная» и лучше; injury — норма «Нет», отклонение = «Внимание». Сводная «Следить» по экрану (без самочувствия) — 34% дней; при желании ужесточается в JSON без кода.

## Д. Архитектура

Статусы групп считает **сервер в `/api/today`** (ui_standard: UI не создаёт шкал). Минимальный аддитивный контракт:

```
signals: { summary, groups: [{ key, status: normal|watch|attention,
  items: [{key, label, value, unit, baseline, deviation, status, note}], advice? }] }
readiness_history: [{date, score}]        // 14 дней, пустые дни — null
sync_freshness: { oldest_source, last_sync_at }
week: { planned_tss_to_date, actual_tss, days: [{date, status}] }
```

Конфиг — `config/thresholds.json` + загрузчик `models/thresholds.py` (дефолты из текущих констант). Сосуществование: «Сигналы» — единственная витрина метрик; «Состояние» = кольцо + статус + свежесть + полоска 14 дней; «Что требует внимания» (gate-конфликты) не заменяется; ProposalCard, обратная связь, подсказка Garmin — без изменений; `AdherenceStrip` превращается в «Эту неделю»; коуч-карточка = разбор `TodayDecisionStoryFull`.
