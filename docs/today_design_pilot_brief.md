# Today: пилот дизайн-процесса

26 сентября 2026. #634 / PR #635. Процесс: #636 / PR #637, `docs/design/workflow.md` в ветке `codex/design-workflow`. Пользователь поручил применить процесс к Today с Luna. Статус: интерактивный кандидат для оценки; окончательная приёмка владельцем не заявляется.

## Задача и границы

Утром спортсмен видит состояние сейчас, тренировки и необходимость действия, не читая большой вводный текст. После раскрытия получает факторы и ограничения. Scope первого пилота — визуальная готовность и компактное самочувствие в существующей композиции Today. Недельная аналитика, новые поля baseline, модель восстановления и полноценный после-тренировочный поток не входят; они сохраняются в дальнейшей работе #634.

Class B: намеренное изменение порядка информации на мобильном экране и раскрытия источника самочувствия. Публичные DTO и domain behavior неизменны. Root — Supervisor/Spec для brief и интеграции; Luna — UI / Design Specialist в изолированном checkout. Один writer на каждом этапе. Никаких изменений чужой рабочей копии или живой БД.

## Информация и действие

Один заметный индикатор восстановления с числом, статусом и свежестью. Цвет/длина показывают серверную оценку, не вычисляют допуск. На мобильном состояние предшествует тренировке. Тренировки остаются главным исполняемым содержанием; независимые сессии и брик сохраняют структуру и переход.

Самочувствие — компактные плитки всех переданных items, без фильтрации «хороших», скрытия травмы и расчёта severity. Метки состояния missing/invalid и status stale/unavailable сохраняются. Техническая provenance доступна по раскрытию; неизвестное время ответа не превращается в точный timestamp. Ошибка загрузки не равна отсутствию симптомов.

Действие остаётся серверным `next_action`: спокойный день без фиктивного выбора, предложение с существующими вариантами, caveats видимы. Не добавлять CTA на основании score. Существующие approve/reject и feedback selection неизменны.

TodayReadinessDriver не содержит raw_value/baseline — подтверждено `web/lib/types.ts`. Сравнение «сегодня / обычно» из prose не извлекать. Если оно понадобится следующему варианту, точный handoff — добавление структурированной проекции в Domain/API, не UI regex.

## Оценка владельцем

Предпросмотр содержит явный selector синтетических сценариев и отключённое сохранение. После предъявления спросить, что пользователь считывает первым и понятно ли сегодняшнее действие. Текущий запрос разрешает создание кандидата; окончательный дизайн не считается принятым без оценки. Не требовать нового подтверждения самой разрешённой доработки.

## Результаты

Проверено 27 сентября: web lint и production build прошли; 6 E2E (design pilot, multisession, readability, decision story) прошли за 47.24 s; 27 focused smoke прошли. Ruff для нового теста и launcher, git diff --check прошли. Визуально проверены desktop dark и mobile light; снимки четырёх сочетаний темы/ширины сохранены в `docs/screenshots/today-design-pilot/`.

Luna реализовала UI в отдельном checkout. Read-only Luna передала review без блокирующих замечаний по согласованным инвариантам; завершающий turn агента остановился по лимиту. Supervisor интегрировал изменения и выполнил проверки.

Воспроизводимый предпросмотр: `python scripts/preview_today_ui.py` из корня checkout с установленными web dependencies. Использовать проектный Python. Открыть http://localhost:3001; порты 3002 и 8001 обслуживают Next и fixture API. Все данные синтетические, POST/PUT/DELETE возвращают 409. Ctrl-C завершает собственные процессы. Fixtures хранятся в `tests/e2e/fixtures/today_preview/`.

Оценка владельца ожидается. After-workout, частично выполненный брик, полный accessibility-аудит и реальный личный день этой проверкой не покрыты.
