# Прямая отправка плавания в Garmin с повторами

Issue #788, Class A. Начальный baseline AI Trainer `c049fbb`, частный Garmin AI Trainer `0.4.0`. Владелец отдельно подтверждает реальную отправку и слияние. SpecDD опирается на критерии #788 и действующую модель неизменяемых программ и назначений из #764. ASR-SEC-1, ASR-REL-1/2/3, ASR-MOD-2/3 и ADR-0001 применяются через точную версию, предварительный просмотр, локальную запись попытки и выделенный API.

## Результат

Из назначения текущего плана спортсмен открывает предпросмотр Garmin, видит дату, версию, длину бассейна, группы, число повторов, упражнения и отдых. Подтверждение создаёт одну тренировку. UI отдельно показывает проверку сохранённой тренировки, её назначение в календаре и отсутствие подтверждения синхронизации с устройством. Автоматическая и повторная отправка при неизвестном состоянии исключены.

## Контракт

- Garmin MCP сохраняет одноуровневые группы как `RepeatGroupDTO` с `numberOfIterations` и `skipLastRestStep`. Дочерние шаги, порядок, текст и теги проходят сверку после создания. Плоские старые черновики сохраняют хеш и семантику, беговой путь сохраняется. Контрольный ориентир — 2200 м, 59 исполняемых шагов, 17 пауз по 30 с, группы 6×, 4× и 18×.
- Проекция использует только выбранную сохранённую V1 или V2 программу. Типизированный стиль, упражнения, оборудование и фиксированная пауза переносятся в доступные поля Garmin. Метры кратны длине бассейна. Отсутствующие теги, включая специальный подтип упражнения, нельзя выводить из текста. Текст тренера остаётся подсказкой. Вложенность, диапазоны, неоднозначный последний отдых, непредставимые указания, превышение лимита текста или незафиксированный отдых возвращают причину с узлом и запрещают отправку. Один цикл можно передать без технической группы.
- Локальный API явно включаемого транспорта привязан к серверу. Web передаёт идентификатор назначения и текущий checkpoint на стадии предпросмотра и идентификатор точного черновика на стадии подтверждения. Сервер проверяет дату, fingerprint программы и актуальность назначения перед резервированием попытки. Черновик и журнал Garmin не читаются браузером напрямую. В демо живая отправка недоступна.
- Состояние Garmin хранится отдельно от Intervals.icu. Одна попытка на назначение, квитанция повторного подтверждения возвращается из журнала, неопределённый исход не создаёт повторный POST. Запись в календарь происходит только после успешного сверенного сохранения. Ссылка в квитанции строится по подтверждённому Garmin ID. Ошибки и провайдерные логи не утрачивают статус и не раскрывают авторизацию.
- Сопоставление факта, перенос и удаление Garmin-событий, расписание синхронизации часов, автоматический пересчёт TSS и изменение существующего Intervals-маршрута вне этого выпуска.

## Проверки

- Офлайн fixtures покрывают 6×/4×/18×, различия в каждом третьем и четвёртом повторе, старые плоские черновики, нарушения и readback. CI не получает исходник личных тренировок или реальные маршруты доступа.
- API и web проверяют переключение канала, подтверждение, сохранённый результат и отказ на суммарно несовместимой структуре. Контракты обновляются вместе с фикстурами. Повтор после сбоя возвращает доступную квитанцию или явный неопределённый статус.
- Короткая отправка FR965 выполняется после отдельного подтверждения точного предпросмотра. Сверка Garmin Connect и наблюдение на устройстве фиксируются отдельно.

## Запуск и восстановление

Для локального запуска нужен установленный Garmin AI Trainer 0.4.1 с действующей авторизацией. Конфигурация FastAPI `GARMIN_SWIM_MCP_SCRIPT` указывает на абсолютный путь установленного `server/readonly_proxy.py`. Без неё новый канал скрыт. После согласованного обновления сервера откройте «План → Календарь тренировок тренера → Доставка на Garmin → Garmin Connect напрямую». «Сверить результат Garmin» читает квитанцию или календарь по ID существующей тренировки. Оно не создаёт новую запись. Если сервис закрыт для обычных пользователей через локальную или self-hosted настройку, новую точку доступа нельзя публиковать без штатной защиты развертывания.

Локальные команды проверки запускаются из корня AI Trainer. `python -m ruff check .`, `python scripts/run_isolated_tests.py -q tests/smoke/test_garmin_swim_delivery.py tests/smoke/test_swim_delivery_calendar.py`, `npm --prefix web run contract:extract -- --check`, `npm --prefix web run lint`, `npm --prefix web run build` и `python -m pytest -m e2e tests/e2e/test_swim_delivery_ui.py -q`. Последний сценарий подменяет Garmin и Intervals.icu в отдельной базе. Повторный просмотр квитанции после перезагрузки должен показывать одну отправку и ссылку Garmin.
