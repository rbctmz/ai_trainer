# Учитывать CSS при автоматическом планировании плавания

- Задача [#765](https://github.com/rbctmz/ai_trainer/issues/765).
- Программа работ [swimming_trainer_program_execplan.md](swimming_trainer_program_execplan.md).
- Основа main 8af1e40, 23.11.2026.
- Автор Codex. Независимая проверка по PR. Решение о слиянии за владельцем.

## Change Class and Scope

Class A в рамках #765. Сборка нового автоматического плана передаёт
сохранённый CSS в существующий снимок зон единым входом для распределения,
материализации тренировок и ограничений входной нагрузки. CSS здесь —
пороговый темп в секундах на 100 м. Каталог уже умеет строить по нему
диапазон темпа. Ручное ревью, использовано 0 из 2 раундов.

## Evidence and RED

**Observed**. Две изолированные сборки с профилями CSS 110 и 130 вернули
по четыре тренировочных назначения плавания с целью relative_rpe.
Значения CSS проверены чтением из каждой тестовой базы.

**Inferred**. build_zone_snapshot в api/planning_service.py не передаёт
CSS в каталог. Сравнение назначений с разным CSS по одной форме сборки
опровергло бы эту гипотезу, если бы появился разный точный темп.

**Verified by**. Синтетический тест через tests/planning_fixtures.py
запустил preview/confirm и прочитал принятый план. Для обеих величин
сохранилась цель relative_rpe.

## Acceptance and Public Contracts

Одинаковая новая сборка с CSS 110 и 130 сек/100 м сохраняет одни и те же
определения тренировок и соответствующие диапазоны темпа в секундах на
100 м. Наличие и величина CSS видны через существующий target_provenance.
Если CSS отсутствует, остаётся текущая цель по субъективному усилию.
Редактирование текущего цикла сохраняет закреплённые авторские версии.

OpenAPI, TypeScript, SQLite и кэш интервалов остаются прежними.
Существующие target.kind, target.unit и provenance уже допускают CSS.
Новых таблиц, курсоров и миграций нет. Существующие планы и их история
читаются по сохранённому снимку цели. Новый CSS применяется при явной
сборке нового плана с действующим подтверждением.

## Identity, Failure and Recovery

Снимок строится из профиля, уже включённого во входы текущей сборки.
Изменение профиля между предпросмотром и подтверждением обрабатывает
существующая проверка актуальности. Выбор авторской программы остаётся
по закреплённому ID и версии. Для отката достаточно откатить коммит.
История сохранённых тренировок остаётся доступной как записана.

## Verification

Запустить через run_isolated_tests.py парный сценарий в test_api_planning.py,
проверки сборки, оценки готовности к публикации, каталога и переноса
авторских ссылок между контрольными версиями календаря. Потом Ruff и CI.

Из архитектурного каталога затронуты ASR-REL-1 и ASR-REL-2. Цель
материализуется из снимка профиля, а при отсутствии CSS каталог применяет
имеющуюся политику субъективного усилия. ADR 0001 сохраняет общий доменный
каталог с явным API-контрактом.
