# Инструкция для внешнего тестера AI Trainer

Это инструкция для технического атлета, который участвует в пилоте: как
поднять продукт, подключить свои данные, пройти основные сценарии и сообщить
о проблеме. Полный пошаговый запуск для первого тестера без Garmin описан в
[`intervals_primary_quickstart.md`](intervals_primary_quickstart.md) — здесь
та же схема, но с акцентом на ежедневное использование и отчётность.

## Что это

AI Trainer — локальный (self-hosted) персональный AI-тренер: синхронизирует
активности и восстановление из Intervals.icu (Garmin Connect — опционально),
строит исполняемый план по цели и доступному времени, а AI-коуч объясняет
нагрузку и предлагает корректировки с подтверждением и откатом. Основной
интерфейс — web (FastAPI + Next.js). Демо-режим работает без ключей, но для
пилота нужно подключить реальные данные.

## Что понадобится

- Docker и Docker Compose plugin (рекомендованный путь) — или локально Python
  3.10+/Node.js (`./run_web.sh`, см. README).
- Персональный API-ключ Intervals.icu: Settings → Developer → Create API Key.
- Ключ AI-провайдера (OpenAI / Anthropic / DeepSeek / Google / локальный
  Ollama) — нужен для реального коуча; без него можно тестировать остальные
  сценарии (демо-коуч или пропустить коуч-диалог).
- Около часа на первый запуск и прохождение чеклиста.

## Быстрый старт

### 1. Подготовьте окружение

```bash
git clone https://github.com/rbctmz/ai_trainer.git
cd ai_trainer
cp .env.example .env
```

В `.env` заполните минимум:

```dotenv
INTERVALS_ICU_API_KEY=<ваш ключ>
INTERVALS_ICU_ATHLETE_ID=0
INTERVALS_ICU_BASE_URL=https://intervals.icu
PRIMARY_ACTIVITY_SOURCE=intervals
PRIMARY_WELLNESS_SOURCE=intervals
```

`GARMIN_EMAIL`/`GARMIN_PASSWORD` оставьте пустыми (Garmin не требуется).
Если эти поля заполнены, синк выполняется и по Garmin тоже (активности и
wellness); с пустыми полями данные идут только из Intervals.icu.
Ключ AI-провайдера — по инструкции в `.env.example` (например,
`DEFAULT_AI_PROVIDER=deepseek` + `DEEPSEEK_API_KEY=...`).

### 2. Пароль для входа

```bash
docker run --rm caddy:2 caddy hash-password --plaintext 'ваш-пароль'
```

Вставьте полученный хэш в `.env`:

```dotenv
DOMAIN=
BASIC_AUTH_USER=trainer
BASIC_AUTH_HASH='$2a$14$вставьте_хэш'
```

Одинарные кавычки вокруг хэша обязательны.

### 3. Запуск

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Дождитесь `healthy` у API и откройте http://localhost:8080. Введите логин
`trainer` и выбранный пароль. Порты API `8000`/web `3000` наружу не публикуются.

### 4. Проверка и синхронизация

- На «Обзоре» карточки источников: `Intervals.icu — Настроен`,
  `Garmin Connect — Не настроен`.
- «Проверить подключение» → успех.
- «Синхронизировать Intervals.icu» → на «Обзоре» появляются тренировки,
  нагрузка и readiness; страницы «Сон» и «HRV» показывают источник метрик.

Первый синк загружает стартовое окно истории; повторный — идемпотентен.

## Ежедневное использование

- **`/today`** — главная страница: сегодняшняя сессия, готовность, TSB.
- **`/planning`** — первый план: карточка онбординга → цель/часы/дни →
  предпросмотр → подтверждение. Затем здесь видны недели, plan/fact и
  корректировки.
- **`/activities`** — журнал: под каждой тренировкой подпись основания TSS
  («по мощности, FTP N», «по пульсу», «по темпу, CSS м:сс/100м»).
- **`/dashboard`** — обзор нагрузки и формы (CTL/ATL/TSB, readiness).
- **`/hrv`** и **`/sleep`** — восстановление с источниками метрик.
- **`/coach`** — диалог с AI-коучем: вопросы о восстановлении/нагрузке/плане,
  предложения изменений с подтверждением и откатом.

## Что проверять в первую очередь

- Профиль атлета (карточка на дашборде): FTP, LTHR, беговой темп, CSS
  плавания — значения с источником и датой синка.
- TSS по видам: вело с мощностью — «по мощности», бег — «по пульсу»,
  плавание — «по темпу, CSS ...».
- План: построение, подтверждение, появление сессии в `/today`.
- После реальной тренировки: сессия матчится в plan/fact на `/planning`.
- Экспорт окна (ICS/TCX/FIT) и доставка в Intervals.icu: обновляются только
  события AI Trainer.

## Частые проблемы

- **Порты заняты** — переопределите:
  `API_PORT=8010 WEB_PORT=3010 ./run_web.sh` (локальный путь) или меняйте
  публикацию в `docker-compose.yml`.
- **«Intervals.icu не настроен»** — проверьте ключ/`ATHLETE_ID` в `.env` и
  перезапустите: `docker compose up -d --force-recreate`.
- **Синк упал с ошибкой** — исправьте причину и повторите: грязный интервал
  не продвигает курсор и данные не теряются.
- **Смотреть логи** (могут содержать личные метрики — не публикуйте их как
  есть):
  `docker compose logs --tail=100 api web caddy`.
- **Полный сброс пилотных данных** — осознанно и только при необходимости:
  `docker compose down -v` (удаляет историю и планы).

## Как сообщать о багах

Создайте issue через «New issue» — форма «Баг-репорт тестера» подставится
автоматически и попросит заполнить только нужные поля (окружение, источник
данных, шаг чеклиста, что делали/ожидали/получили). Впечатления и идеи можно
оставить в форме «Фидбек тестера».

Полезно указать `tss_method`, значения профиля и источник данных — это ускоряет
воспроизведение. Скриншоты и логи прикладывайте без личных метрик.

## Конфиденциальность

Приложение хранит личные тренировочные метрики локально (SQLite в Docker
volume). Логи и скриншоты перед публикацией проверяйте и маскируйте: они могут
содержать пульс, HRV, координаты и другие персональные данные. Свои API-ключи
не передавайте никому и не вставляйте в issues.
