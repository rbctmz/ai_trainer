# Принципы экрана «Сегодня»

Статус: рабочий стандарт UI по решениям владельца продукта от 25 сентября 2026 года. Область — представление существующих данных и действий. Это не новая спецификация расчёта восстановления или изменения плана.

## Назначение

За несколько секунд спортсмен должен понять, что запланировано сегодня, есть ли важное отклонение и требуется ли его действие. В обычный день экран помогает выполнить тренировки. Если сервер предлагает изменение, экран показывает конкретные варианты и последствия выбора.

## Иерархия информации

1. Дата и тренировки дня: вид спорта, название, длительность, этапы и целевые значения.
2. Один визуальный показатель восстановления с числом, текстовым статусом и свежестью данных. Цвет не заменяет текст и не означает допуск к тренировке.
3. При отклонении — короткое видимое предупреждение. При доступном предложении — варианты и подтверждение. Недостаток данных не выдаётся за предложение изменить план.
4. Подробности: факторы, даты измерений, источники, основания предложения. Неизвестные и устаревшие данные обозначаются явно.
5. Самочувствие, вчерашний результат и недельный контекст поддерживают основное действие, а не вытесняют его.

В спокойный день нет призыва принять решение, которого не существует, повторного блока готовности или абзаца «вмешательство не требуется». Важные ограничения и предупреждения о безопасности не прячутся в раскрывающиеся подробности.

## Геометрия и визуальный язык

Сегодня наследует общий контейнер приложения из `web/app/layout.tsx`: `max-w-5xl`, внешние поля `px-4 sm:px-6`. Внутреннее ограничение ширины всей страницы запрещено. Границы основного контента совпадают с навигацией и другими основными экранами.

Используются существующие токены поверхности, границ, текста, акцента и скругления. На широком экране восстановление располагается рядом с тренировкой; на узком блоки складываются вертикально. При ширине 390 px нет горизонтального скролла, обрезанного текста и потерянных кнопок. Основные данные читаются без открытия подробностей. Интерактивные элементы имеют заметный фокус и доступны с клавиатуры; выбранный вариант обозначается текстом/формой и `aria-pressed`.

## Несколько тренировок и брик

Независимые тренировки показываются отдельными блоками в порядке API. UI не придумывает время начала, порядок выполнения или связь между ними. Общий показатель восстановления не повторяется для каждой тренировки.

Брик — связанная последовательность этапов. Между этапами явно показывается переход и его длительность, если она есть в данных. Связь определяется видом сессии и идентификатором группы, а не совпадением видов спорта. Нельзя связывать соседние независимые тренировки или разные брики. Неизвестное время перехода не заменяется нулём или вымышленным значением.

## Предложение изменить план

Видимы только варианты, предоставленные существующим серверным потоком. Сохраняются текущие ограничения доступности и подтверждения. UI не рассчитывает новый план, не меняет рекомендацию и не добавляет собственные варианты.

Для выбранного варианта показываются «Сейчас» и «После подтверждения»: тренировки, известная длительность и нагрузка. Для изменения нескольких дней показывается каждый затронутый день и полный предоставленный состав тренировок. Перенос содержит конкретные даты. Изменение недельного времени и нагрузки показано отдельными числами; отсутствие значения обозначается как «Не указано».

Рекомендация сервера и текущий выбор различимы. Кнопка называет действие: «Оставить план», «Подтвердить снижение», «Подтвердить перенос». Сам выбор карточки ничего не сохраняет. Причина и исходные данные доступны рядом через раскрытие. Обычный экран не содержит внутренних статусов, идентификаторов, checkpoint, enum или названий алгоритмов.

## Тексты

Русский язык, короткие подписи и конкретные действия. Известные названия каталога переводятся; пользовательские названия сохраняются. TSS допускается как показатель с пояснением в подробностях. Не следует заменять технический абзац другим длинным абзацем. Числа, статусы и причины отображаются из API, а не сочиняются браузером.

## Проверка каждой доработки

Проверять обычный день, две независимые тренировки, брик, доступное предложение, отсутствие предложения при отклонении, неизвестные/устаревшие данные, загрузку и ошибку. Для предложения проверить переключение вариантов, правильную подпись подтверждения и отсутствие записи при простом выборе. Проверить десктоп и мобильный экран, клавиатуру, отсутствие переполнения и единственный основной индикатор восстановления.

Снимки тестовых примеров маркируются как синтетические. Успешные lint/build и браузерные проверки не заменяют оценку владельцем продукта на реальном сценарии.

## Текущая итерация

Class C: локальное представление существующего потока, без изменения доменных правил, API и выбора вариантов. Observed: Today содержал собственный `max-w-2xl`, общий layout — `max-w-5xl`. Verified by: чтение обоих компонентов; браузерная проверка ширины выполняется при проверке итерации. Доработка ограничена Сегодня; старое представление общих карточек на других экранах сохраняется.

Проверка итерации 25 сентября: `npm --prefix web run lint` и `npm --prefix web run build` прошли; пять браузерных тестов Today прошли, новый тест повторно прошёл после уточнения связи этапов. Ещё 27 focused smoke-проверок контрактов и свежести прошли. Браузер проверил совпадение ширины Today и навигации (разница не более 2 px) на 1280 и 390 px, отсутствие горизонтального переполнения, один индикатор восстановления, переход брика, переключение кнопки подтверждения без POST-запроса и сохранение всех предоставленных тренировок при сравнении дня. Отсутствующие недельные значения остаются неизвестными, а не нулевыми.

Примеры находятся в `docs/screenshots/today-multisession-ui/`: `two-*`, `brick-*`, `proposal-*`. Это синтетические UI-данные, не персональная рекомендация и не свидетельство качества доменного решения. Рабочий localhost и живая база этой итерацией не обновлялись.
