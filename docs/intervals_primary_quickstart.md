# Быстрый старт AI Trainer с Intervals.icu

Этот сценарий предназначен для первого технического тестера без Garmin. Он
поднимает локальный однопользовательский стек в Docker, загружает активности из
Intervals.icu и приводит к первому плану. Сон и HRV из Intervals.icu появятся в
M4; в этом сценарии синхронизируются только активности.

## 1. Подготовьте конфигурацию

В корне свежего клона выполните:

```bash
cp .env.example .env
```

Откройте локальный `.env` и заполните:

```dotenv
INTERVALS_ICU_API_KEY=<ваш персональный API key>
INTERVALS_ICU_ATHLETE_ID=0
INTERVALS_ICU_BASE_URL=https://intervals.icu
PRIMARY_ACTIVITY_SOURCE=intervals
```

`GARMIN_EMAIL` и `GARMIN_PASSWORD` оставьте пустыми. API key хранится только в
локальном `.env`: не вставляйте его в интерфейс, issue, лог или коммит.

Для локального входа через Caddy создайте bcrypt-хэш:

```bash
docker run --rm caddy:2 caddy hash-password --plaintext 'выберите-пароль'
```

Затем задайте в `.env`:

```dotenv
DOMAIN=
BASIC_AUTH_USER=trainer
BASIC_AUTH_HASH='$2a$14$вставьте_полученный_хэш'
```

Одинарные кавычки вокруг хэша обязательны: bcrypt содержит символы `$`.

## 2. Проверьте и поднимите стек

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Дождитесь состояния `healthy` у API и откройте
[http://localhost:8080](http://localhost:8080). Введите логин и пароль Caddy.
Порты API `8000` и web `3000` наружу не публикуются.

## 3. Проверьте Intervals.icu

На пустом экране «Обзор» карточка должна показать:

- `Intervals.icu — Настроен`;
- `Garmin Connect — Не настроен`;
- выбранный источник `Intervals.icu`.

Нажмите «Проверить подключение». Успех показывает, что Intervals.icu доступен,
не раскрывая список календарей или ключ.

Если карточка пишет, что Intervals.icu не настроен, проверьте переменные в
`.env` и перезапустите контейнеры:

```bash
docker compose up -d --force-recreate
```

## 4. Синхронизируйте активности

Нажмите «Синхронизировать Intervals.icu». Первый запуск загружает стартовое
окно истории; повторный запуск идемпотентен и использует сохранённую границу
синхронизации. После завершения на «Обзоре» появятся тренировки и показатели
нагрузки.

Ошибка или частичный ответ отображаются в этой же карточке. Исправьте причину и
повторите синк: грязный интервал не продвигает курсор мимо потерянных данных.

## 5. Постройте первый план

Откройте [/planning](http://localhost:8080/planning). В карточке первого плана:

1. проверьте предложенные цель, часы и доступные дни;
2. для режима «подготовка к событию» подтвердите A-гонку или введите дату
   вручную; без гонки выберите тренировочную цель;
3. сохраните параметры;
4. нажмите предварительный просмотр;
5. подтвердите план.

План должен появиться на `/planning`. Затем откройте
[/today](http://localhost:8080/today): там видна ближайшая запланированная
сессия. Синхронизация сама план не строит — параметры и подтверждение обязательны.

## 6. Остановка и сохранность данных

Обычная остановка сохраняет SQLite в named volume:

```bash
docker compose down
```

Следующий `docker compose up -d` использует ту же историю и план. Команда ниже
удаляет volume и всю локальную тренировочную историю; используйте её только для
намеренного полного сброса:

```bash
docker compose down -v
```

Для диагностики:

```bash
docker compose ps
docker compose logs --tail=100 api web caddy
```

Не публикуйте логи без проверки: они могут содержать персональные метрики.
