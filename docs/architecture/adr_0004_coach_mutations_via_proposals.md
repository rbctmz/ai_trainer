# ADR 0004: Мутации коуча — только через approval-gated proposals

- Status: Accepted (эволюция решения «read-only coach»)
- Date: 2026-07-20
- Related: `models/ai_tools.py::propose_plan_build/propose_plan_adjustment`, `api/planning_service.py` confirm/rollback, контур #154/#209

## Context

Исходное решение — строго read-only коуч (безопасность превыше autonomy): LLM не может испортить данные. Но продуктовая цель — агентный контур доверяемых решений, где система ПРЕДЛАГАЕТ изменение плана. Полный read-only делал коуча комментатором.

## Decision

Эволюция, не отмена: LLM по-прежнему не пишет в данные НАПРЯМУЮ никогда. Любая мутация проходит трёхфазный контракт:

1. **Propose**: инструмент строит preview без persist (`persist=False`), с точным `base_checkpoint_id`.
2. **Confirm (human-in-the-loop)**: применение только по явному действию пользователя, fail-closed на устаревший чекпойнт.
3. **Append + rollback**: применение создаёт новую версию (ADR-0006), откат — ещё одну; история не переписывается.

Аналитика считает числа, LLM только объясняет (принцип контура); авто-apply не существует ни в одном пути.

## Consequences

- ✅ Autonomy без потери безопасности; WoZ подтвердил, что actionable-карточка с подтверждением работает там, где текстовый совет игнорируется («переговорный комплаенс», 2026-07-12).
- ⚠️ Подъём автономии (Confirmed-Act) допустим только по измеренной калибровке decision_log — не по календарю.
