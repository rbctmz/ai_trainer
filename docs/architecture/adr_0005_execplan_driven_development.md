# ADR 0005: ExecPlan-driven development

- Status: Accepted (закрепляет практику, проверенную #205/#209/#190/#228)
- Date: 2026-07-20
- Related: `.agent/PLANS.md`, `docs/*_execplan.md`, AGENTS.md («Claude GitHub Action Norms»)

## Context

Кодовую базу параллельно развивают несколько агентов (Codex, Claude Code, Claude GitHub Action) и человек-checker. Issues/PRs сами по себе не переносят контекст между агентами и сессиями: холодный агент должен уметь продолжить работу с одного документа.

## Decision

1. Крупная/архитектурная работа ведётся через ExecPlan — самодостаточный living-документ (`Purpose`, `Design`, `Milestones`, `Progress`, `Surprises`, `Decision Log`, `Retrospective`) по правилам `.agent/PLANS.md`.
2. RED-гейты каждого милстоуна регистрируются и коммитятся ДО реализации; GREEN — отдельным коммитом; каждая ревью-находка checker'а закрывается через свой RED до фикса.
3. Якоря инвариантов — к неизменяемому ВХОДУ, не между двумя производными (урок #205 M3b, повторён #228).
4. Milestone-размерные задачи делегируются Action'у одним упоминанием; многораундовые треки остаются в длинных локальных сессиях.

## Consequences

- ✅ Шесть checker-раундов #209 и живые прогоны Action показали: процесс переживает смену исполнителя и исчерпание квоты без потери контекста.
- ⚠️ Издержка — дисциплина ведения документа; компенсируется тем, что ExecPlan и есть handoff.
