# Доставка авторской тренировки в Intervals.icu и на FR255

Issue #764, parent #760. Class A — запись у провайдера, identity и новый API.
Кандидат начинается с 856cacb. Порядок работ в [ExecPlan](swim_delivery_execplan.md).
Владелец решения о слиянии и живой отправке — пользователь. Проверка diff
независимая, ручной native review с бюджетом 0/2 на старте.

## Сценарий и границы

Спортсмен открывает одно авторское назначение текущего цикла, просматривает
точную версию, дату, бассейн, шаги, паузы и ограничения целевого канала. После
подтверждения AI Trainer передаёт одну тренировку в Intervals.icu. Результат
сообщает, что принял и вернул Intervals.icu. Получение и поведение на FR255
подтверждаются отдельно на устройстве. Первый профиль — бассейн 25 м.

Доставка по календарю не меняет локальную дату, исходный текст, версию
программы, факт или TSS. Обычная доставка автоплана не управляет этими
событиями. Нет batch, двусторонней синхронизации, автоотправки, Garmin
Personal API, перерасчёта истории. Бассейн 50 м и открытая вода получают
явный статус совместимости, пока у этих профилей нет собственной приёмки.
Рабочие данные и личные программы не входят в fixtures и CI.

## Публичные контракты

- Python строит конечную последовательность шагов из V1 и V2. Каждый шаг
  знает исходный узел и путь по повторам. Лист хранит точные метры либо
  исходный режим отдыха, секундные границы или число выдохов, текст,
  вид упражнения, снаряжение и субъективную инструкцию. Отдых даёт 0 м.
- Повторы разворачиваются в порядке исполнения. Пропускается только явно
  исключённый последний отдых каждой группы. Для unspecified с явным
  шагом отдыха виден последний шаг и предупреждение об отсутствии
  отдельного правила. Размер экспорта ограничен 100 шагами, документ не
  изменяется. Неизвестная совместимость, несовместимые отрезки, диапазон
  повторов, попытки, незавершённый разбор и таймер с завершением текущего
  цикла не превращаются в вымышленные метры, таймеры или число кругов.
- Фиксированный отдых остаётся фиксированным. Открытый отдых, в том числе
  выдохи, заканчивается по Lap. Приблизительный отдых передаётся как
  ручной Lap с исходным ориентиром, явно видимый в предпросмотре. Для
  provider bridge техническая длительность, если понадобится компилятору,
  никогда не является назначенной паузой. Её допустимость должна быть
  проверена отдельно на readback и FR255. Send-off сюда не входит.
- Intervals получает native description с явным pool length и mtr. Текст
  подсказки проходит проверку синтаксиса, чтобы числа и переносы строк из
  заметок не создали таймер, цель или новый шаг. Нативные режимы
  оборудования неизвестны. Если передаётся текстовая подсказка, это
  видно до отправки. В исходной версии весь текст остаётся доступен.
- Аддитивная пара API preview/confirm для одного назначения, зеркало в TS
  и новый сценарий в contract registry. Preview возвращает точный target,
  шаги, предупреждения и явный статус несовместимости. Confirm принимает
  идентификатор предварительного просмотра и явное согласие. API открытия
  старых версий остаётся читающим. Новых настроек для пользователя нет.

## Identity, отказ и повтор

Preview связывает текущий цикл, checkpoint, назначение, дату, fingerprint
программы и точный provider payload. Confirm перед записью заново проверяет
выбранный цикл, версию, дату и ограничения, истечение preview, а также
доступность состояния провайдера. Используется отдельный стабильный
external_id на назначение. Общий writer оставляет эти external_id вне
cleanup. Повтор того же подтверждения возвращает сохранённый результат
или выполняет только сверку. Прерванная попытка сначала ищет прежнее
событие, повторная запись при неизвестном результате запрещена. Изменение,
пропажа или дубликат известного события требуют разбирательства. #702
задаёт эту политику, массовая доставка остаётся за его рамками.

Локальные preview/receipt задают отдельную аддитивную таблицу с явным
владением, expiry и учётом при полном сбросе. Запись Attempt резервируется
перед сетевым действием. Сетевой вызов выполняется вне SQLite-транзакции.
После write отдельный GET сверяет дату, тип, длину бассейна, метры, порядок,
вид пауз, подсказки и отсутствие добавленных целей. Успешный POST без
достаточного readback оставляет результат неопределённым. Уточнение
статуса не создаёт дубль. Автоматического удаления событий для отката нет.
Аннулирование синтетического тестового события, если понадобится, имеет
отдельно согласованную точную область.

## Проверяемая приёмка

| Сценарий | Проверка |
| --- | --- |
| V1 и V2, три учебных программы | 2200/2000/1900 м, порядок, вложенность, 50/60/120 с, Lap, исходные тексты |
| Последний отдых include/omit/unspecified | Точный список листьев и путь по повторам |
| Непредставимый шаг или бассейн | Точная причина и узел, provider write отсутствует |
| Потеря дистанции, вида паузы, шага или заметки | Искажение обнаруживается в разобранном workout_doc |
| Повтор, неизвестный исход, чужая правка, смена версии | Повторная запись не происходит, история сохранена |
| Календарь и подтверждение в web | Изолированный Chromium и заполненные контракты |
| FR255 после отдельного согласия | Появилась контрольная тренировка, совпали бассейн, метры, фиксированный и ручной отдых и граница последнего отдыха |

RED для первых трёх строк использует молчаливую потерю метров в текущем
legacy-сериализаторе как исходное наблюдение. Дальше тесты целевого
контракта должны падать до появления реализации. Результаты фиксируются
в ExecPlan. ASR-REL-1/2/3, ASR-MOD-2/3 и ASR-SEC-1 применяются через
неизменяемую версию, защиту от неполной записи, аддитивный контракт и
изолированные fixtures. ADR-0001 определяет Python → API → web. CI, review,
human merge и проверка на устройстве имеют отдельные доказательства.
