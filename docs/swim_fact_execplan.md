# Сопоставить плавательную программу тренера с фактом

Это живой ExecPlan для #765 по .agent/PLANS.md. Контракт и матрица проверок
описаны в [спецификации](swim_fact_slice_spec.md).

## Purpose / Big Picture

После синхронизации пловец открывает выполненную тренировку и видит, что
получилось по каждой сопоставимой серии. Система учитывает метры, время
плавания и время отдыха по отдельности и показывает, каких данных не хватает.
При автоматическом планировании темп в бассейне учитывает сохранённый CSS,
то есть пороговый темп в секундах на 100 м.

## Surprises & Discoveries

**Observed**. Оба нормализатора в models/activity_intervals.py возвращают
для 25/50/75 м значения 0.03/0.05/0.07 км.

**Inferred**. Округление в общей функции преобразования скрывает исходные
метры от разбора серии. Это опроверг бы компактный результат с исходными
метрами для обоих источников.

**Verified by**. Вызов normalize_garmin_splits_payload и
normalize_intervals_payload на main 8af1e40 с одинаковыми расстояниями вернул
0.03 км для 25 м и 0.07 км для 75 м. Отдельного значения в метрах нет.

## Context and Orientation

models/activity_intervals.py приводит ответы Garmin и Intervals.icu к
компактным словарям. services/sync.py сохраняет круги Garmin, а
services/activity_intervals.py загружает интервалы Intervals.icu и читает
локальный кэш. data/activity_store.py хранит этот кэш как JSON по ID
активности. api/routers/activities.py передаёт его карточке, а
web/lib/types.ts описывает форму ответа.

api/planning_service.py передаёт снимок зон в сборку плана. Канонический CSS
хранится в swim_threshold_pace_seconds_per_100m. models/plan_vs_fact.py
содержит общее сопоставление шагов и отрезков. Перед добавлением разбора
нужно определить, какие данные подтверждают бассейн, метры, отдых и границы
серии, и как показать частичное покрытие при неоднозначности.

## Plan of Work

Первый срез добавляет distance_meters для свежих кругов и групп, проверяет
его прохождение через кэш и API, а затем обновляет TypeScript-контракт.
Следующий срез воспроизводит разрыв CSS сравнением двух сборок с CSS 110
и 130 сек/100 м. Порог влияет на автоматически назначенный темп. Указания
тренера о субъективном усилии сохраняют исходное значение.

После этого добавить сравнение серий для трёх контрольных ДЗ. ДЗ 1 сравнивает
темп внутри круга, ДЗ 2 позволяет сопоставить сотни, ДЗ 3 сохраняет описание
субъективного усилия и показывает доступные измерения. Каждый исходный
отрезок участвует в сопоставлении один раз. Карточка получает результат
через явный API-контракт.
