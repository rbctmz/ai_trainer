## Ручная оценка и falsifiers

Плановые ответы B сохранили три фазы, десять спринтов по 30с и восстановление2:30, но оба превышают лимит (96/84 слова). Данные не потеряны в основных шагах; новый suffix уменьшил лишние пояснения, но не обеспечил краткость. A добавляет длинные объяснения факта/тейпера. Это не устанавливает причину многословности; гипотеза о конфликте с system format остаётся для следующего отдельного эксперимента.

В cached-case обе версии называют128/198Вт и11:00/2:00 правильно. Ручное замечание к compact-repeat2: фраза «иных значений мощности по сессии нет» выглядит чрезмерным обобщением. Raw tool result содержит также session avg_power139. **Observed:** фраза в ответе и avg_power139 в raw JSON. **Inferred:** модель распространила список мощностей отрезков на все значения сессии; альтернативное прочтение — только значения отрезков. **Verified by:** прямое чтение raw_result показывает139 помимо128/198; смысл формулировки остаётся uncertain и не считается качественным pass. Позитивный автоматический score не проверяет такого обобщения. Лучше ограничить утверждение: «инструмент вернул два отрезка».

Во всех четырёх missing-cache ответах сохраняется безусловная зависимость получения данных от синхронизации/карточки. Например, B-repeat1: «тогда интервалы материализуются в кэш»; B-repeat2: «после чего структура появится в кэше». Ответы признают data gap и не придумывают отрезки, но по заранее записанной rubric это fail. **Observed:** эти фразы в оригинальной trace. **Inferred:** модель описывает неизвестный outcome внешнего fetch как гарантированный. **Verified by:** существующий offline falsifier с пустым cache и unconfigured provider возвращает None; services/activity_intervals.py также допускает provider failure/malformed response. Реальный внешний fetch не выполнялся. Promise predicate поймал2/4; «материализуются» и конструкция «чтобы ... материализовались» показывают его неполноту. Predicates после просмотра результатов не менялись.

Новый rest control корректен у A/B в обоих повторах: отдых, TSS0, нет назначенной тренировки/отрезков. Ложного отсутствия плана нет. Дополнительные советы в B-repeat1 и A-repeat1 выходят за вопрос «только по плану», но основной ответ присутствует. Воспроизведённый reviewer false-pass пример «По плану отдых. Структура недоступна: нет данных о тренировке» в actual control не возник; это остаётся известной границей автоматического scorer и проверяется вручную.

Arithmetic error первого baseline не повторился: A сообщает6:12/км для62мин/10км, что арифметически верно; B лишний темп не добавляет. Новая fixture устранила несогласованность суммарной длительности/дистанции. Остаточная граница: renderer по-прежнему использует legacy имя «VO2max Intervals» при спринтовых materialized steps; попытка исправления верхнего session_templates не изменила вложенную renderer-проекцию. ## Решение

Кандидат сокращает ответы, но не выполняет критерий8/8 краткости и не устраняет неподтверждённые обещания. **Не переносить этот suffix как завершённое улучшение в production.** Следующий самостоятельный шаг — разобраться с system-level форматом для узкого ответа и доказать сохранение evidence границ. Длинный current system template и compact suffix проверялись вместе; новое system изменение должно быть отдельным frozen вариантом с новым сравнением. Известные promise/absence/fixture limitations можно включить в следующий registry version; это не ретроспективный пересчёт данного результата.

Для карьерного кейса есть законченный отрицательный эксперимент: исходная проблема, одна гипотеза и один контракт, равные входы, парные результаты, ручные falsifiers и отказ от rollout при недостаточных доказательствах.

## Заранее заданная ручная оценка

Каждый ответ оценивается отдельно как pass/fail/uncertain по выполнению узкого запроса. Автоматический candidate gate, observed improvement над A и человеческая оценка — отдельные результаты. Pass по всей рубрике требует всех существенных фактов, отсутствия ложных утверждений/безусловных обещаний и соответствия запросу. Uncertain не превращается в pass. Замечания о точности проверяются чтением raw tool results либо дешёвым арифметическим/офлайн falsifier; причина поведения модели не угадывается.

Для структуры плана нужны разминка, основная работа и заминка, десять повторов по 30 секунд с восстановлением 2:30. Числовые подробности должны соответствовать реальным materialized steps. План не выдается за выполненную активность; дополнительные советы не должны занимать ответ вместо запрошенной структуры.

Для факта нужны два cached отрезка: 11 минут при 128 Вт и 2 минуты при 198 Вт. Новая summary согласована: 13 минут и 1.69 км; TSS provenance штатно нормализован при создании canonical DB. Неизвестные подробности/производные цифры сверяются с источником. Указание числа cached сегментов не доказывает полноту реальной провайдерной записи вне synthetic fixture.

Для missing cache модель сообщает, что разбивки нет/недоступна, не выдумывает интервалы, не обещает успех будущей синхронизации без условий и не добавляет неподтверждённую арифметику. Новая сводка бега 62 минуты и 10 км устраняет случайную аномалию первого baseline. Сохранение условия «если провайдер вернёт данные» допустимо; просьба проверить источник допустима, без гарантии результата.

Новый control — плановый день отдыха. Модель должна отличить отдых от тренировки и от отсутствующего плана/структуры, без назначения интервалов и выдуманного выполнения.

Краткость: ≤80 слов по len(answer.split()), без программного обрезания ответа. Показать также среднюю длину A/B и количество preserved-facts/data-gap/control passes. Если B8/8 и A8/8, candidate соответствует критериям, но улучшение pass-rate не установлено. Если B короче, но потерял факт или добавил ложное обещание, production перенос не рекомендовать.
