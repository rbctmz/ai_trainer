# Coach #528: первый baseline настоящего runtime

Эксперимент выполнен 2026-10-13 на `deepseek-flash`, код `839febe`, реестр `coach_runtime_eval_v1`. Цель — измерить выбор инструментов и свойства реального ответа, чтобы получить проверяемый инженерный кейс. Итог: **PARTIAL**. Сквозной путь работает, но по заранее заданным автоматическим предикатам прошли только **2/6** попыток. Это baseline для улучшения, а не доказательство качества спортивных рекомендаций и не закрытие #528.

Неизменённый [live-baseline.json](live-baseline.json) содержит все видимые запросы/ответы модели, вызовы инструментов, данные инструмента, проверки, narrative gate, hashes временных БД и время. `human_assessment=pending` в исходном JSON сохранён: ниже находится отдельная качественная оценка интегратора. Работа reviewer касалась корректности runner, а не экспертной оценки тренировочных советов.

## Человеческая оценка

Плановые ответы корректно передают шаги и отличают план от отсутствующего факта, но повторяют одну мысль в нескольких разделах и добавляют советы, которых вопрос не требовал. Во втором ответе появляется рекомендация «до старта ... повторять такие спринты не нужно»: этот эксперимент не проверяет основания такого совета. Это выход за узкий вопрос о структуре, а не доказанный физиологический дефект.

Ответы об отрезках называют правильные мощности и длительности. Однако формулировки «Это вся ... информация — других отрезков ... нет» и «Всего 2 отрезка за 62 мин» требуют осторожности: фикстура содержит 13 минут cached intervals при общей длительности 62 минуты. Полнота провайдерной записи в этом эксперименте не проверялась. Проверки подтверждают перечисленные значения, а не полноту сессии.

Оба ответа без кэша честно отказываются придумывать отрезки, но дают слишком длинное объяснение и уверенно обещают: после синхронизации или открытия карточки интервалы появятся. В первом также встречается неверный пересчёт «~3:30 км/мин». Эти смысловые проблемы не покрыты автоматическими проверками, хотя весь trial уже fail по краткости. Следовательно, per-property pass не доказывает общую корректность ответа.

## Evidence discipline и дешёвые опровержения

**Observed:** 4/6 ответов превышают заранее установленный предел 80 слов, хотя все вопросы содержат «Коротко». Источник: JSON final_answer и существующий `style_brevity_respected`. **Inferred:** обязательный формат synthesis prompt (тезисы, практические выводы, следующий шаг; до примерно 300 слов) может поощрять лишние разделы. **Verified by:** повторный подсчёт `len(answer.split())` даёт 155, 189, 59, 57, 163, 131; чтение сохранённого system prompt подтверждает более длинный формат. Причина не установлена: A/B с другим response contract не проводился, два коротких ответа показывают, что длинный формат не неизбежен.

**Observed:** missing-cache repeat 1 выводит «~3:30 км/мин» из 32.5 км за 62 минуты. **Inferred:** модель ошиблась в арифметике либо единицах; это могло бы опровергнуться совпадением хотя бы с одной правильной величиной. **Verified by:** `32.5 / 62 = 0.5241935 км/мин`, `62 * 60 / 32.5 = 114.46 сек/км`, то есть примерно 1:54/км. Missing-cache repeat 2 сообщает 1:54/км корректно. Arithmetic/units property отсутствует в frozen registry.

**Observed:** missing-cache ответы обещают появление интервалов после синхронизации/карточки. **Inferred:** уверенность о будущем внешнем fetch не обоснована текущим cached-only tool result. **Verified by:** офлайн вызов `fetch_activity_intervals` с пустым кэшем, synthetic provider link и `is_configured=False` возвращает `None`, без сети. Исходный код также допускает provider error/malformed response с отсутствующим кэшем. Это опровергает безусловную гарантию; синхронизация реального аккаунта здесь не выполнялась.

## Границы доказанного

Три сценария × два повтора — маленькая выборка. Holdout — один заранее помеченный сценарий, а не статистически значимый независимый набор. Production prompt не настраивался на ответы. Автоматические проверки lexical/numeric и ограничены; они не оценивали весь смысл, медицинскую безопасность, безопасность реального изменения плана или пользу спортсмену. Сценарии используют четыре инструмента чтения и non-streaming shared runtime; API orchestration, SSE, сохранение чатов, recovery loop и delivery не запускались.

Переиспользованная synthetic fixture несовершенна: бег 32.5 км за 62 мин и 13 минут отрезков при общей велосессии 62 мин. Это оказалось полезным наблюдением для data-gap поведения, но не должно выдаваться за типичные данные атлета. Следующая версия реестра должна явно отделить согласованные данные от намеренно противоречивых. Этот baseline не переписывается после просмотра результатов.

## Следующий ограниченный шаг

Сначала улучшить краткость ответа для узких вопросов, сохраняя нужные факты и честный data gap. Проверить гипотезу отдельным сравнением baseline и явного компактного response contract; менять production после измерения, не из этого отчёта автоматически. На development использовать два первых сценария, для проверки переноса добавить новые unseen сценарии. Отдельный future case должен проверять, что отсутствие кэша не превращается в обещание успешного будущего fetch. Арифметика и полнота evidence — кандидаты в следующий versioned registry, а не ретроспективное изменение результата.

## Воспроизведение

Из корня checkout, после установки существующих dependencies и активации venv:

    python scripts/run_coach_runtime_eval.py --provider scripted --today 2026-10-13 --repeats 2 --output /tmp/coach-scripted-new.json

Scripted режим проверяет runner, не качество модели. Для нового платного baseline (в этом запуске повторные live calls не делались):

    python scripts/run_coach_runtime_eval.py --provider deepseek --live --env-file /path/to/private/.env --today YYYY-MM-DD --repeats 2 --output /tmp/coach-live-new.json

Использовать текущую дату для live, поскольку начальный native system prompt использует production calendar; `--today` фиксирует даты fixture/synthesis/gate и не подменяет production clock. Модель/settings меняются во времени; сравнение требует фиксировать их и версии. Output создаётся эксклюзивно: существующий файл останавливает запуск до model calls. CLI exit 1 здесь означает завершённый baseline с quality failures; exit 2 означает INCONCLUSIVE выполнения/провайдера.
