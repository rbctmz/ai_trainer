# Сопоставить фактические серии с заданием тренера

Задача [#765](https://github.com/rbctmz/ai_trainer/issues/765), Class A.
Кандидат начинается с main 6d8fbda. [ExecPlan](swim_fact_execplan.md).
До 2 раундов ручного ревью. Решение о слиянии за владельцем.

## Поведение

Первый профиль — программа бассейна 25 м, развёрнутая тем же проектором,
что использует доставка. Проектор факта получает упорядоченные наблюдения
одного источника. Для каждого шага он возвращает исходные позиции строк,
точные метры, наблюдаемое время плавания, отдыха и полное время. Темп
в секундах на 100 м рассчитывается из наблюдаемого времени плавания.

Рабочий шаг принимает только последовательные положительные метры,
целые длины бассейна с точной суммой. Один зарегистрированный отрезок
используется максимум один раз. Крупный фактический отрезок нельзя
разделить на несколько плановых шагов. После неизвестного расстояния,
переполнения или неожиданной паузы последующие шаги остаются без факта.
Пауза без фактической строки отмечается как неизвестная. Если следующая
строка содержит явно измеренные положительные метры, её можно оставить
для следующего рабочего шага. Известный отдых требует отдельной строки
с нулевыми метрами и подтверждённым временем отдыха. Открытый отдых
сохраняет исходную подсказку о выдохах.

Для ДЗ 1 темп сравнивается внутри каждого круга. Полный круг показывает
разницу самого быстрого и медленного отрезка. Для ДЗ 2 сохраняются темпы
отдельных сотен. Для ДЗ 3 диапазон субъективного усилия остаётся
инструкцией тренера. У одного источника может быть покрытие по дистанции
без достаточных данных о времени для темпа.

## Привязка и границы API

Сервис привязывает факт через paired_event_id Intervals.icu
к единственной подтверждённой записи отправки в
swim_delivery_previews. Из записи берётся сохранённый ID и точная версия
программы. Смена даты, текущего плана или новой версии программы не
переносит эту привязку. Дублированное или повреждённое подтверждение
оставляет сравнение недоступным. Карточка отдельно от общего разбора
получает поле swim_series_fact в GET /api/activities/{id}. Гарминовские
movingDuration и elapsedDuration сохраняются раздельно. Обычный duration
для сравнения считается неопределённым. Источник выбирается по покрытию
дистанции, затем темпа, затем отдыха. При равенстве используются круги
Garmin. Переход к Intervals.icu отражён в used_fallback. Данные разных
источников не смешиваются.

TypeScript и сгенерированный контракт описывают опциональное поле.
Проверки используют синтетическую программу и временные базы. Миграция истории, изменение
TSS, отправка на часы и обновление рабочего кэша в срез не входят.

## Границы проверки

| Вход | Ожидаемый результат |
| --- | --- |
| 4 круга 50, 100 и 150 м | 4 независимых сравнения темпа внутри круга |
| Сотни с разным фактическим временем | Отдельные значения на 100 м |
| 3 повтора с усилием от 50 до 90 процентов | Видно авторское указание и наблюдаемый темп |
| 300 м одним фактическим отрезком вместо трёх сотен | Разбиение недоступно |
| Старые округлённые метры или неполные часы | Честное частичное покрытие |
| Отдельная пауза, пропущенная пауза, лишняя пауза | Известный отдых, неизвестный отдых или остановка сопоставления |

ASR-REL-1 и ADR 0008 сохраняют идентичность и историю. ASR-REL-2
оставляет отсутствующие показания неизвестными. ASR-MOD-2 и ADR 0001
оставляют сопоставление и единицы измерения в общей Python-модели.

Сверить RED и GREEN на трёх контрольных ДЗ, источниках с разной
детализацией и отсутствии времени. Независимый checker и владелец
принимают итоговый срез на текущем коммите после CI.
