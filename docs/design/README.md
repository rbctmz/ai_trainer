# Дизайн web-продукта AI Trainer

Рабочая версия 26 сентября 2026, задача [#636](https://github.com/rbctmz/ai_trainer/issues/636). Этот пакет задаёт процесс и предложения для следующих UI-срезов. Он не утверждает, что текущие экраны уже соответствуют стандарту, и не меняет существующие API/доменные контракты. Принятие через обычный repository review; новые правила не дают агентам полномочий на merge.

## С чего начинать

Прочитать [карту экранов и UI-стандарт](ui_standard.md), затем [процесс и пилот Today](workflow.md). Для задачи использовать [краткий brief](../templates/ui_design_brief.md) в её существующем issue/spec/PR, без обязательного отдельного документа. [Аудит](audit_2026_09_26.md) отделяет проверенный код от направлений для проверки. [План внедрения](rollout_execplan.md) фиксирует границу текущего docs-среза и последующие реализации.

Источники истины разделены: задача и её acceptance задают желаемое поведение; Python/API — смысл данных и допустимые действия; этот стандарт — представление; `web/app/globals.css`, `web/tailwind.config.ts`, `web/app/layout.tsx` — реализованные токены и геометрия; типизированные fixtures и `/showcase` — проверяемые примеры. Разногласие между слоями записывается как вопрос/дефект, а не разрешается скрытым вычислением в UI.

Общие правила имеют приоритет над случайным решением отдельной карточки. Экранный стандарт уточняет их. Новое исключение записывается в brief с причиной и затронутым сценарием; оно само по себе не требует дополнительного approval. Решения владельца в текущей задаче сохраняют приоритет.

## Что уже есть и что ещё предстоит

Уже есть общие токены light/dark, общий layout, реальные web-компоненты, dev-only showcase и изолированный E2E harness. Архив `docs/redesign_guide/` посвящён старому Streamlit; его примеры не являются инструкцией для Next.js. Streamlit остаётся поддерживаемым fallback до parity согласно ADR-0001.

Первое применение — продолжение [#634](https://github.com/rbctmz/ai_trainer/issues/634) / [PR #635](https://github.com/rbctmz/ai_trainer/pull/635). Его Today-стандарт пока находится в отдельной ветке; после интеграции согласовать его с этим пакетом, не отменяя решений владельца. Этот docs PR не закрывает родителя #610 и не переносит UI-код из #635.

Figma — необязательный инструмент композиции. Канонические результаты (решение, состояния, проверяемый пример) остаются доступны из репозитория. Новый Storybook или отдельная дизайн-платформа не обязательны: сначала расширяется существующий showcase. Изображение само по себе не проверяет выбор, раскрытие, ошибку или сохранение; для них нужен интерактивный пример с синтетическими данными.
