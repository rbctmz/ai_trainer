# Программа тренера: проверяемый web-сценарий

Синтетическая программа `exact_program_v2`, настоящие React-компоненты, API и
временная SQLite. Три тренировки2200/2000/1900м, общая дистанция6100м. Здесь нет
личной программы, исходных видео или данных спортсмена.

Первый экран показывает исходное состояние, действие предпросмотра и серверный
объём программы. На широком экране исходник/диалог и структура расположены рядом;
на телефоне исходник/диалог раскрываются отдельно, а объём остаётся на первом
экране. Серии раскрываются внутри своей тренировки. Предупреждения показывают
название тренировки и читаемый текст с цветовой границей.

Снимки `program-{light,dark}-{1280,390}.png` показывают всю страницу; файлы
`*-first-screen.png` — первый экран900CSSpx. Ширина320 также проверена на
переполнение и видимость объёма, без отдельного снимка. `metadata.json` содержит
время, HEAD на момент запуска и SHA256 каждого UI-файла: снимки сделаны на рабочем
дереве, поэтому именно хеши файлов связывают их с проверяемой реализацией.

В браузере проверены переход из Коуча, сохранение точного исходника до AI,
несколько тренировок, уточнение/одна правка, ручные формы, прямые правки,
предпросмотр всей программы, явное подтверждение и повторное открытие версии.
Отдельные случаи покрывают потерю ответов, stale/expired preview, недоступное
чтение результата, V1, диапазоны/выдохи/временной цикл и pinned exercise rev1 после
обновления справочника до rev2. Источник состояния — сервер; браузерный буфер
восстанавливает только незаконченный ввод и не подтверждает сохранение.

Клавиатурная проверка: фокус на открытой форме, Tab на первый выбор и возврат
к исходной кнопке после отмены. Контраст основной кнопки и текста предупреждения
проверен по фактическим CSS-цветам в обеих темах (значения в metadata). Это не
сертификация всей страницы/WCAG или проверка экранным диктором. Замечены и
исправлены конфликт цвета основной кнопки, потеря фокуса при размонтировании
кнопки и слишком низкое положение мобильной сводки.

Первоначальная ручная форма также выбирает exact exercise revision до первой
записи структуры: сервер получает ссылки и атомарно закрепляет снимки. Поиск
клавишей Enter не отправляет программу, а дозировка/снаряжение задания не
переписываются выбранной техникой.

Воспроизведение из активированного тестового окружения с Node22 и Chromium:

    AI_TRAINER_CAPTURE_SWIM_EVIDENCE=1 python scripts/run_isolated_tests.py -m e2e tests/e2e/test_swim_visual_acceptance.py -q

По умолчанию тест не перезаписывает снимки. Все runtime-процессы/базы принадлежат
изолированному harness; перед очисткой он проверяет владение путями. Синтетический native provider
проверяет интеграцию, а не качество живого AI. Владелец ещё не принимал этот UI;
снимки/тесты не заменяют его решение о review/merge и не разрешают live rollout.
