# Evidence-first spikes

`spikes/` содержит короткие воспроизводимые эксперименты для дорогих неизвестных
в API, данных, производительности, конкурентном доступе и математических моделях.
Spike отвечает на вопрос до окончательной спецификации; он не является частью
продукта и не заменяет обычные тесты.

Канонические правила процесса находятся в
`docs/AI_Feature_Development_Workflow.md`, шаг 0. Этот файл задаёт формат
репозиторного артефакта.

## Имена каталогов

Используй стабильный номер GitHub issue:

    spikes/issue-NNN-short-name/

Пример:

    spikes/issue-444-bike-hr-tss/

В каждом каталоге обязателен `README.md`. Скопируй `spikes/TEMPLATE.md`, заполни
его до запуска эксперимента и обнови после наблюдения результата.

## Что разрешено хранить

- небольшой исполняемый прототип;
- очищенные синтетические фикстуры;
- точную команду запуска;
- короткие обезличенные результаты;
- вердикт, границы доказанного и рекомендацию.

## Что запрещено

- импорты из `spikes/` в `api/`, `web/`, `services/`, `models/`, `data/` или
  другие продуктовые модули;
- реальные учётные данные и содержимое `.env`;
- персональные метрики, сырые приватные ответы провайдеров и полные журналы
  реального окружения;
- неконтролируемые внешние записи или платные вызовы;
- выдача spike за регрессионный тест или готовую реализацию.

## Завершение

Эксперимент получает ровно один вердикт:

- `VALIDATED`;
- `PARTIAL`;
- `INVALIDATED`;
- `INCONCLUSIVE`.

После вердикта перенеси подтверждённое поведение в SpecDD/ExecPlan, обычные
тесты, контракт или ADR. Одноразовый код, не нужный для воспроизведения
архитектурного решения, удали. Если артефакт остаётся, README должен явно
объяснять, почему он полезен и что не является производственным кодом.
